El presente documento técnico detalla la arquitectura, librerías, decisiones de diseño y mecanismos de seguridad implementados en el Portal de Noticias para dar cumplimiento integral a las especificaciones funcionales y de seguridad computacional solicitadas en el caso práctico.

1. Librerías y Tecnologías Utilizadas

El backend fue desarrollado sobre el entorno de ejecución Node.js (v22+) utilizando una arquitectura desacoplada basada en servicios RESTful y cliente SPA (Single Page Application).

2. Arquitectura del Código y Organización de Módulos

La aplicación sigue una separación estricta entre capa de persistencia, lógica de negocio, middlewares de seguridad y cliente web:

Backend y API REST (/src y server.js)
  • server.js: Servidor HTTP/HTTPS, cabeceras de seguridad CSP/HSTS, CORS y manejador global de errores.
  • src/database/schema.sql: Esquema de 7 tablas relacionales y triggers SQL de auditoría.
  • src/database/db.js: Conexión SQLite, migraciones automáticas y seed inicial de datos.
  • src/middleware/auth.js: Verificación de JWT, cookies HttpOnly y ciclo de vida de tokens.
  • src/middleware/permissions.js: Autorización RBAC en tiempo real contra BD.
  • src/middleware/sanitizer.js: Limpieza XSS y validación de tipos y tamaños.
  • src/middleware/upload.js: Validación de imágenes por firmas binarias (Magic Bytes).
  • src/routes/: Rutas de autenticación (auth), noticias (noticias) y administración (admin).
Frontend SPA (/public)
  • public/index.html: Interfaz de usuario completa (Portal, Modales de Auth, Editor y Dashboard).
  • public/js/api.js: Cliente HTTP que inyecta Authorization: Bearer y gestiona el refresco automático de tokens.
  • public/js/auth.js: Control de estado del usuario autenticado, login, registro y cierre de sesión.
  • public/js/news.js: Lectura protegida, filtros por categoría, búsqueda y publicación con carga de imágenes.
  • public/js/admin.js: Panel interactivo para gestión de usuarios, matriz de permisos en tiempo real y bitácora.
  • public/js/app.js: Enrutamiento de vistas SPA y control de ventanas modales.

4. Cumplimiento de Requerimientos de Seguridad Computacional

1. Cifrado de Contraseñas (bcrypt)

Las contraseñas se almacenan como hashes generados con bcryptjs utilizando un factor de coste de 12 (bcrypt.genSaltSync(12)). Nunca se almacenan en texto plano ni se utilizan algoritmos reversibles. El sanitizador excluye los campos de credenciales para preservar la integridad exacta de la clave elegida.

2. Comunicación Cifrada (HTTPS / TLS)

server.js incorpora soporte nativo para TLS mediante el módulo https. Incluye el script npm run certs para generación de certificados de desarrollo y activa automáticamente la cabecera Strict-Transport-Security: max-age=31536000; includeSubDomains (HSTS).

3. Gestión Segura de Tokens JWT y Refresh Tokens

• Access Token: Vigencia corta de 15 minutos (ACCESS_TOKEN_EXPIRY = '15m'), firmado con algoritmo HS256.
• Refresh Token: Token criptográfico de 7 días almacenado en BD con detección de reutilización y revocación automática (rotación de tokens).
• Almacenamiento Seguro: El token de acceso vive únicamente en la memoria de la aplicación JS (no en localStorage) y se respalda con cookies HttpOnly, SameSite=Strict y Secure.
• Secretos: Las claves secretas se cargan desde .env y el servidor rechaza valores por defecto o de baja entropía.

4. Autorización Verificada en el Servidor

Cada endpoint protegido ejecuta authenticateToken y requirePermission, consultando la base de datos en tiempo real. La seguridad no delega en que la interfaz oculte botones o vistas, garantizando que peticiones directas vía HTTP sean validadas rigurosamente.

5. Validación y Sanitización de Entradas (XSS y SQL Injection)

• Inyección SQL: Todas las consultas a la base de datos SQLite utilizan prepared statements con parámetros vinculados (?), eliminando cualquier concatenación directa.
• XSS: El middleware sanitizeInput elimina etiquetas peligrosas (<script>, <iframe>, eventos en línea como onload/onerror). En el frontend, el DOM se manipula con textContent y replaceChildren().
• Límites de Entrada: Validación de longitud máxima en nombres, títulos, contenidos y correos electrónicos.

6. Protección contra Ataques de Fuerza Bruta y DoS

• Bloqueo Temporal de Cuenta: Tras 5 intentos fallidos consecutivos de contraseña (MAX_FAILED_ATTEMPTS = 5), la cuenta se bloquea automáticamente durante 15 minutos respondiendo HTTP 423 Locked.
• Rate Limiting: Middleware en memoria (rateLimiter.js) que impone límites de solicitudes por ventana de tiempo en endpoints de autenticación y API general, respondiendo HTTP 429 Too Many Requests.

7. Registro de Auditoría con Trazabilidad e Inmutabilidad

La tabla auditoria almacena fecha y hora ISO, ID de usuario, acción realizada, detalles y dirección IP real (getClientIp). A nivel de base de datos, los triggers de SQLite trg_auditoria_no_update y trg_auditoria_no_delete abortan cualquier intento de modificación o borrado de eventos, garantizando un registro inmutable (append-only).

8. Manejo Seguro de CORS

CORS está configurado en server.js mediante una lista blanca estricta (allowedOrigins). Se prohíbe explícitamente el uso de comodines (*) al operar con credenciales habilitadas (credentials: true).

9. Principio de Mínimo Privilegio y Prevención de Huérfanos

Cada rol posee únicamente los privilegios indispensables. Además, la función wouldOrphanCriticalPermission impide que un administrador revoque el permiso roles.gestionar o usuarios.gestionar si ningún otro rol lo conserva, previniendo el bloqueo total de la administración del sistema.

10. Manejo de Errores sin Fuga de Información

Se deshabilita la cabecera x-powered-by de Express y se implementa un manejador global de errores que captura excepciones internas y responde con mensajes JSON genéricos (HTTP 500/400), impidiendo la divulgación de trazas de pila (*stack traces*), sintaxis SQL o versiones de software.

Extra: Carga Segura de Imágenes (Magic Bytes)

Las imágenes subidas por los redactores se almacenan en storage/uploads/ (fuera del directorio public/). El servidor genera nombres aleatorios criptográficos, limita el tamaño a 5 MB y valida los primeros bytes binarios del archivo (*Magic Bytes*) para confirmar que es un JPG, PNG, GIF o WEBP real antes de aceptarlo.
